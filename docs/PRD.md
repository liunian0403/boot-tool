# PRD：Windows 开机小助手（v4）

> 来源：产品经理产出（HYPE-44 issue 评论 `01a1b8fc`）+ 后续两次用户反馈修订（HYPE-46）。作为研发与验收依据。
>
> **v2 → v3（HYPE-46，2026-11-08）**：①新增 **F7 安装后开机自启**（用户明确需求）；②新增 **F8 启动后右下角弹窗**展示本次开机用时；③新增 **F9 时钟数据源兼容层**——现场反馈 `QueryInterruptTime` 在部分 Windows 11 版本上已不从 `kernel32.dll` 导出，v0.2.0 因此无法启动，本版把"取不到就失败"改为"分层降级"，并把实际生效的数据源写入启动日志；④安装包产物更名 `boot-tool-setup.exe`（Inno Setup 7 警告 `setup.exe` 会被 Windows 应用兼容层 shim 加载，存在 DLL 劫持面）；⑤AC8 相应更名，新增 AC9–AC11。发布 tag **v0.3.1**。
>
> **v3 → v4（HYPE-46，2026-11-08，用户反馈："刚开机显示耗时一个多小时，肯定不对"）**：**口径修正，本版为破坏性语义变更**——用户机器开启 Windows **快速启动（Fast Startup）**，关机实为休眠，**内核计时器跨关机连续累计**，因此 `QueryInterruptTime / GetTickCount64 / LastBootUpTime` 都不能代表"这次开机"；v3 用它推导出的"本次开机用时 1 小时 53 分"是错的。v4 改为：**开机耗时与开机完成时刻一律取自系统事件日志的启动打点**（内核启动 → 登录完成），**已运行时长自"登录完成"起算**；内核计时仅作读日志失败时的降级兜底并在界面标注。新增 F10 与 AC12–AC14。



### 1. 背景与目标

**背景**：用户需要知道电脑"什么时候开的机、开了多久"，系统自带信息分散在任务管理器、`systeminfo`、事件查看器里，且口径不统一（含不含睡眠时间经常对不上）。上一轮交付用户反馈"安装包打不开"，暴露两个问题：交付形态预期错位（只给了单文件 exe）、启动失败无可见报错——本轮已在需求层修复（见 §3、AC0）。

**目标用户**：普通 Windows 用户 + 需要关注机器运行状态的运维/开发人员。

**业务目标与成功指标**：
- 开机时刻与系统权威来源（任务管理器"启动时间"）误差 ≤ 1 秒
- 时长显示在任意时刻误差 ≤ 1 秒，连续运行 7 天不漂移
- 双击后 ≤ 3 秒出现主窗口，任何失败可见可查（AC0）
- 启动后 3 秒内出数，常驻资源占用可忽略（见 §6）

### 2. 数据采集口径（关键，技术方案必须遵守）

> **v4 修订**：本节原以"内核单调计数"为唯一口径，在**快速启动**机器上会把上一次会话的时长算进这次开机（现场：刚开机显示 1 小时 53 分）。v4 起，**面向用户的两个数字分别取自系统启动打点与登录完成打点**，内核计数只在读不到日志时兜底。

| 概念 | 定义 | 采集方式 |
|---|---|---|
| 本次开机耗时 | **内核启动 → 登录（桌面可用）** 的时长 | 系统事件日志：`Kernel-Boot 27 BootType`（混合/冷启动标记）或 `Kernel-General 12`（冷启动标记）→ `Winlogon 7001`（登录完成）之差。**不含 BIOS 自检**（固件时间不在系统日志里，并在界面注明） |
| 开机完成时刻 | 本次会话"桌面可用"的绝对时刻 | 同上的 `Winlogon 7001` 记录时间（本地时区展示） |
| 已运行时长 | 自"开机完成时刻"至今 | 首次读数由墙钟差得出，此后用单调计数推进（抗 NTP 校时/手工改表，含睡眠/休眠） |
| 内核在线时长（仅诊断） | 内核 sm 单调计数（含睡眠，但**快速启动时不归零**） | `QueryInterruptTime`（分层降级，见 F9）；只写入启动日志，不作为界面数字 |
| 累计开机时长（P1） | 跨会话累加的历史总时长 | 本地持久化：关机/退出前写入，启动时读取合并；断电场景下次启动自愈 |

**口径硬性要求**（技术方案需逐条说明实现方式）：
1. **与系统自身打点一致**：开机耗时与开机完成时刻必须能对得上系统事件日志（`Winlogon 7001` / `Kernel-Boot` / `Kernel-General`），且**不得使用程序自身启动时间**推算开机完成时刻。
2. **快速启动正确**：混合启动（BootType=1）后，界面数字必须是"这次"的，不能把上一次会话的时长算进来；界面应标注"（快速启动）"以免用户困惑于秒级数字。
3. 睡眠/唤醒、休眠/恢复后"已运行"数值连续，不重置、不跳变。
4. 时区变化、夏令时切换不改变"开机完成时刻"的展示正确性；墙钟被校时不影响"已运行"的推进。
5. 数据源可降级：任一 API 或日志通道不可用都不得让程序不可用；降级后必须在界面标注并在日志留痕。
6. 读不到系统启动日志时，**宁可显示"未知"并说明原因，也不显示一个明显错误的数字**。



### 3. 功能范围

**P0（MVP，本期必须）**
- F1 开机耗时展示：**本次开机从内核启动到登录完成用了多久**（取自系统事件日志打点，不是内核计时、也不是程序启动时刻）
- F2 已运行时长展示：自"开机完成"起实时刷新（天→秒，秒级常显，尾零省略；英文 `3d 4h 5m 6s`），含睡眠/休眠
- F3 口径对齐：与系统自身事件日志打点对得上（`Winlogon 7001` / `Kernel-Boot 27` / `Kernel-General 12`）
- F4 睡眠/休眠恢复后正确续算
- **F5【新增】双交付形态**：绿色单文件 `boot-tool.exe`（双击即用）+ **安装包 `boot-tool-setup.exe`**（安装向导、开始菜单快捷方式、卸载项）。依据：用户明确称"安装包"，上一轮仅单文件 exe 造成预期错位
- **F6【新增】启动失败可见性**：任何启动失败/内部错误必须弹出可见错误对话框并写入日志（`%TEMP%\boot-tool.log`），**禁止无声退出**——上一轮"打不开"暴露的正是此缺口
- **F7【v3 新增】安装后开机自启**：安装包默认勾选"开机时自动启动"（用户可在安装向导取消），写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（**免管理员**，属于 Windows 标准"启动应用"位置，任务管理器可见可关）；卸载时自动移除。绿色版可手动执行 `boot-tool.exe --install-startup` / `--uninstall-startup` 达到同样效果
- **F8【v3 新增】启动后右下角弹窗**：以自启方式启动时，等待桌面就绪约 3 秒后在**主屏工作区右下角**弹出卡片，展示"本次开机耗时"（大号数字）+ 开机完成时刻 + "点击查看详情"；约 10 秒后自动消失，弹出期间不抢焦点、不占任务栏/Alt-Tab；点击卡片打开主窗口。手动双击启动仍直接打开主窗口（不弹卡片）
- **F9【v3 新增】数据源兼容层**：`QueryInterruptTime` 不再硬依赖单一 DLL 导出，按 `kernelbase → kernel32 → GetTickCount64` 降级；实际数据源写日志。依据：HYPE-46 现场报错 `stage: clock FAILED: QueryInterruptTime: Failed to find QueryInterruptTime procedure in kernel32.dll`（Windows 11 10.0.26300 实测 `kernel32.dll` 已无该导出、仅 `kernelbase.dll` 有）
- **F10【v4 新增】快速启动正确性**：开启 Windows"快速启动"的机器上，本次开机耗时/开机完成/已运行必须是**本次会话**的数字；界面标注"（快速启动）"，并在小字里给出"上次冷启动 X 秒"作为参照，避免"3 秒"让人误以为数据错了


**P1（下一期）**
- 纯运行时长（剔除睡眠）
- 累计开机时长 + 历史会话记录
- 托盘常驻（v3 起自启已提前到 P0/F7，托盘图标仍留 P1）

**P2（有余力再做）**
- 数据导出（CSV）、开机时长提醒、多语言（中/英）

**明确不做（本期）**：性能监控、开机启动项优化、系统体检等发散功能。

**交付物清单【修订】**：
- `boot-tool.exe`（绿色单文件）、`boot-tool-setup.exe`（安装包，v3 更名，理由见文首变更说明）
- `boot-tool-debug.exe`（控制台诊断版，逐步打印启动日志，定位启动失败）
- README：构建/使用说明 + **"打不开？"故障排查章节**（SmartScreen 放行、右键解除锁定、SHA256 校验、`%TEMP%\boot-tool.log` 位置）

### 4. 使用场景

1. **查看这次开机花了多久**：用户刚开机坐下，右下角卡片直接告诉他"本次开机耗时"；想知道机器已经连续跑了多久，点开主窗口看"已运行"。
2. **核对是否该重启**：机器连续运行多天 → 看已运行时长决定是否重启。
3. **对账**：用户怀疑数据不准 → 本工具的数字来自系统事件日志（`Kernel-Boot` / `Kernel-General` / `Winlogon`），事件查看器里能逐条对上。
4. **【新增】首次安装**：用户下载 `boot-tool-setup.exe` 安装 → 开始菜单启动 → 若双击打不开，按 README 排障或运行诊断版定位。
5. **【v3 新增】日常开机（主场景）**：装好之后不用管——每次登录 Windows，右下角自动弹出"本次开机耗时"，看一眼即可收掉；想知道更多细节就点一下卡片打开主窗口。
6. **【v4 新增】开启快速启动的机器**：混合启动只需几秒，卡片会标注"（快速启动）"并给出"上次冷启动 X 秒"作参照，避免"3 秒"被误认为数据错误。

### 5. 验收标准

- **AC0【硬性】可启动性**：双击 `boot-tool.exe` 与 `boot-tool-setup.exe` 安装后的快捷方式，均 ≤ 3 秒出现主窗口、无黑窗；任何启动失败必须弹出可见错误对话框并写日志，**禁止无声退出**。AC0 不通过，其余验收不开始
- **AC1【v4 重定义】开机耗时与开机完成时刻**：与系统事件日志一致（≤ 1 秒）——开机完成时刻 = 该次启动后第一条 `Winlogon 7001` 的时间；开机耗时 = 该时间 − 该次启动的 `Kernel-Boot 27` / `Kernel-General 12` 打点。冷启动、快速启动各验一次
- **AC2【v4 重定义】已运行无漂移**：显示误差 ≤ 1 秒；连续运行 7 天无累积漂移；NTP 校时/手工改表不改变推进速度
- **AC3【v4 重定义】睡眠连续**：睡眠 4 小时后唤醒，"已运行"正确包含这 4 小时且无跳变；"开机耗时/开机完成"不因睡眠改变
- AC4：强制断电后重启，累计数据不损坏、不重复累加（**随 P1 实现时验收，本期 N/A**）
- AC5：系统时区切换后，"开机完成"的展示时刻随本地时区正确变化（耗时为时长，不受影响）
- AC6：启动后 3 秒内显示首屏；空闲 CPU < 0.1%、内存 < 50MB（参考目标，不阻塞验收，真机实测后回填基线）
- AC7：Windows 10/11 中英文系统下展示与功能正常
- **AC8【新增】安装包验收**：`boot-tool-setup.exe` 在 Win10/11 完整走完安装向导，开始菜单出现快捷方式、控制面板可卸载，安装后启动通过 AC0
- **AC9【v3 新增】开机自启**：安装包默认勾选"开机时自动启动"时，`HKCU\...\Run` 出现 `"<安装目录>\boot-tool.exe" --autostart`；卸载后该值消失；安装向导取消勾选则不写入；`--install-startup` / `--uninstall-startup` 可独立完成注册/注销并弹出可见结果提示
- **AC10【v3 新增，v4 调整】右下角弹窗**：以 `--autostart` 启动后 ≤ 5 秒出现右下角卡片（主屏工作区内、距右侧/底部各 16px、不遮挡任务栏），内容为**本次开机耗时**（秒级）+ 开机完成时刻 + "点击查看详情"；约 10 秒自动消失且进程退出；点击卡片打开主窗口；弹窗不抢焦点、不在任务栏出现按钮。重复双击程序不会出现第二个窗口（激活已有实例）
- **AC11【v3 新增】数据源兼容**：在 `kernel32.dll` 无 `QueryInterruptTime` 导出的 Windows 版本（现场为 10.0.26300）上程序可正常启动，日志出现 `stage: clock ok (source=kernelbase.dll!QueryInterruptTime)`；三个数据源全部缺失时才允许报错退出，且必须弹出可见错误框并写明每个尝试过的数据源
- **AC12【v4 新增，硬性】快速启动正确性**：在开启"快速启动"的机器上做完一次"关机→开机"，界面显示的"本次开机耗时"为秒级（不得出现上次会话的累计小时数），"开机完成"为本次登录时间，"已运行"从 0 开始增长；界面标注"（快速启动）"
- **AC13【v4 新增】不得用程序自身启动时间**：开机完成时刻必须来自系统日志打点（`Winlogon 7001`），不得由程序启动时刻或内核计数反推；代码审查 + 日志 `stage: boot-record ok (kind=... ready=... source=eventlog:System)` 双重确认
- **AC14【v4 新增】日志不可读时诚实降级**：系统事件日志读不到（权限/日志被清理/损坏）时，界面显示"本次开机耗时：未知"并提示"已运行按内核计时，快速启动后可能明显偏大"，**不得显示一个编造的数字**；程序仍须可用


### 6. 非功能需求

- 资源占用：常驻内存 < 50MB，空闲 CPU < 0.1%（**假设，待实测校准**）
- 兼容：Windows 10 1809+ 与 Windows 11 x64
- 无网络依赖、无管理员权限要求（基础功能）；不上传任何数据
- 崩溃不拖垮系统；失败可见可查（对话框 + `%TEMP%\boot-tool.log`）

### 7. 开放问题与已拍板决策

**已拍板（不再讨论）**：
1. 交付形态：**双交付**（绿色单文件 + 安装包）——用户"安装包打不开"反馈的直接对策
2. 历史会话/导出：本期砍掉归 P1；AC4 随 P1 验收
3. 展示格式：`3天4小时5分6秒`（尾零省略），英文 `3d 4h 5m 6s`
4. AC6 资源指标：参考目标、不阻塞验收
5. 【v3】开机自启**默认勾选**：用户明确要求"安装后开机自动启动"；仍保留在安装向导中取消勾选的自由
6. 【v3】弹窗节奏：桌面就绪等待 **3 秒**、停留 **10 秒**（可配置常量，改值不需改结构）
7. 【v3】安装包产物更名 `boot-tool-setup.exe`：Inno Setup 7 对名为 `setup.exe` 的产物给出安全警告（Windows 应用兼容层会 shim 加载 `version.dll` 等，存在劫持面）
8. 【v3】时钟数据源降级顺序 `kernelbase → kernel32 → GetTickCount64`：前两者 100ns、第三者 1ms，同属"自启动起算、含睡眠"的计数族，秒级展示下无可见差异
9. 【v4】**开机耗时/开机完成一律以系统事件日志打点为唯一事实源**：`Kernel-Boot 27` / `Kernel-General 12` → `Winlogon 7001`；不使用程序启动时刻、不使用内核计数反推
10. 【v4】**"已运行"从"开机完成（登录）"起算**，不再等同任务管理器"正常运行时间"——后者是内核会话时长，快速启动后会跨关机累计，语义与本产品不符
11. 【v4】**不含 BIOS 自检时间**：固件阶段不写入系统日志（`Kernel-Boot 30` 的计时在关机-开机间隔过长时会被污染，实测同一台机器一次冷启动给出 159.8 秒的假值），为避免误报，界面注明"不含 BIOS 自检"而非猜测一个数
12. 【v4】**读不到日志时显示"未知"**而不是回退成内核计时后再声称是开机耗时（回退值仍显示但明确标注风险）

**遗留开放问题**：
1. 安装包技术选型（Inno Setup / NSIS / 其它）→ **已由技术方案 v2 回答：Inno Setup 7.1.1，见 `docs/design.md` §4 与决策 ADR-1**
2. 上一轮"打不开"的确切根因仍未定位（SmartScreen / 下载损坏 / 静默失败三选一）→ **v3 部分定位：`QueryInterruptTime` 取不到导致的 clock 阶段失败已在现场日志复现（HYPE-46），本版修复；其余路径仍由 F6 兜底**
3. 【v3，P1】弹窗是否要附带"比上次开机快/慢"的历史对比（依赖 P1 累计数据）→ v4 已先给出"上次冷启动 X 秒"的最低版本
4. 【v4，待定】是否把"从上电到桌面"的固件/BIOS 时间也纳入（需要另找固件来源，且在快速启动/关机-开机间隔长的场景不可靠）

**事实与假设说明**：v4 的口径已在本机（Windows 11 10.0.26300 x64，2026-11-08）用真实事件日志验证：12:12:20 的 `Kernel-Boot 27 BootType=1` → 12:12:23 的 `Winlogon 7001`，程序显示"本次开机耗时 3 秒（快速启动）/ 开机完成 12:12:23"，与事件查看器逐条一致；同时拿到上次冷启动 13.7 秒作参照。AC6 资源指标为**待实测项**；AC9–AC14 的本机自测记录见 `docs/test-plan.md` §C、§D。
