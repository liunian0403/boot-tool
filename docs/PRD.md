# PRD：Windows 开机小助手

> 来源：产品经理产出（HYPE-44 issue 评论），Gia 复核后归档于此，作为研发与验收依据。

### 1. 背景与目标

**背景**：用户需要知道电脑"什么时候开的机、开了多久"，系统自带信息分散在任务管理器、`systeminfo`、事件查看器里，且口径不统一（含不含睡眠时间经常对不上）。

**目标用户**：普通 Windows 用户 + 需要关注机器运行状态的运维/开发人员。

**业务目标与成功指标**：
- 开机时刻与系统权威来源（任务管理器"启动时间"）误差 ≤ 1 秒
- 时长显示在任意时刻误差 ≤ 1 秒，连续运行 7 天不漂移
- 启动后 3 秒内出数，常驻资源占用可忽略（见 §6 非功能需求）

### 2. 数据采集口径（关键，技术方案必须遵守）

| 概念 | 定义 | 采集方式 |
|---|---|---|
| 开机时刻 | 本次内核启动的绝对时刻 | WMI `Win32_OperatingSystem.LastBootUpTime`；以任务管理器"启动时间"为对齐基准 |
| 本次开机时长 | `当前时刻 − 开机时刻` | 由开机时刻实时计算；**含睡眠/休眠时间**（与任务管理器"正常运行时间"一致） |
| 纯运行时长（P1） | 剔除睡眠/休眠后的实际运行时间 | `QueryUnbiasedInterruptTime` 或累加电源事件（睡眠/唤醒/休眠/恢复） |
| 累计开机时长（P1） | 跨会话累加的历史总时长 | 本地持久化：关机/退出前写入，启动时读取合并；断电场景下次启动自愈 |

**口径硬性要求**：
1. "本次开机时长"必须与任务管理器"正常运行时间"同口径（含睡眠），否则用户对不上数，视为缺陷。
2. 睡眠/唤醒、休眠/恢复后数值必须连续，不重置、不跳变。
3. 意外断电/强杀进程不损坏已持久化的累计数据；写入需原子（临时文件+替换或 WAL 类做法）。
4. 时区变化、夏令时切换不得引起开机时刻跳变（以单调时钟为主、墙钟仅用于展示）。

> 以上 4 条为口径验收的判定依据，技术方案需逐条说明实现方式。

### 3. 功能范围

**P0（MVP，本期必须）**
- F1 开机时刻展示：本次开机的日期时间
- F2 本次开机时长展示：实时刷新的时长（天-时-分，秒级精度）
- F3 口径对齐：与任务管理器启动时间/正常运行时间一致
- F4 睡眠/休眠恢复后正确续算

**P1（下一期）**
- 纯运行时长（剔除睡眠）
- 累计开机时长 + 历史会话记录（最近 N 次开机时间与时长）
- 开机自启 + 托盘常驻

**P2（有余力再做）**
- 数据导出（CSV）、开机时长提醒（如超过 X 天提示重启）、多语言（中/英）

**明确不做（本期）**：性能监控、开机启动项优化、系统体检等"助手类"发散功能——偏离"精确统计开机时间"这一核心。

### 4. 使用场景

1. **查看本次开了多久**：用户早上开机，晚上想确认机器连续跑了多久 → 打开工具，一眼看到开机时刻和时长。
2. **核对是否该重启**：机器连续运行多天，用户判断是否需要重启 → 看累计/本次时长。
3. **对账**：用户怀疑任务管理器数据不准 → 本工具与其口径一致，可交叉验证。

### 5. 验收标准

- AC1：开机时刻与任务管理器"启动时间"相差 ≤ 1 秒（冷启动、重启、睡眠恢复三种场景各验一次）
- AC2：时长显示误差 ≤ 1 秒；连续运行 7 天后与权威来源仍一致（无累积漂移）
- AC3：睡眠 4 小时后唤醒，"本次开机时长"正确包含这 4 小时，且无跳变
- AC4：强制断电后重启，累计数据不损坏、不重复累加
- AC5：系统时区切换后，开机时刻展示仍正确
- AC6：启动后 3 秒内显示首屏数据；空闲 CPU < 0.1%、内存 < 50MB（假设值，实测后校准）
- AC7：Windows 10/11 中英文系统下展示与功能正常

### 6. 非功能需求

- 资源占用：常驻内存 < 50MB，空闲 CPU < 0.1%（**假设，待实测验证**）
- 兼容：Windows 10 1809+ 与 Windows 11 x64
- 无网络依赖、无管理员权限要求（基础功能）；不上传任何数据
- 崩溃不拖垮系统，异常退出不影响下次数据恢复

### 7. 开放问题（Gia 已拍板，见 docs/design.md §8）

1. 交付形态：单文件 exe / 带托盘常驻的安装版？
2. 是否需要历史会话记录与导出（P1 还是砍掉）？
3. 长时长展示格式：`3天4小时` 还是 `72:04:11`？
4. 资源占用指标 AC6 是假设值，是否需要先做一轮实测再定基线？

---

**事实与假设说明**：§2 的采集方式（WMI LastBootUpTime、QueryUnbiasedInterruptTime）是基于 Windows 公开 API 的**假设**，技术方案阶段需验证其在目标系统上的精度与权限要求；AC6 的资源指标为**假设值**，待实测校准。其余为需求定义。
