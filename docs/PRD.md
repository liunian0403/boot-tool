# PRD：Windows 开机小助手（v3）

> 来源：产品经理产出（HYPE-44 issue 评论 `01a1b8fc`，2026-11-08 重走流程版本），架构师随 `started_2` 技术方案同步归档于此，作为研发与验收依据。v1 → v2 变更三处：①交付形态改为"绿色单文件 exe + 安装包"双交付；②新增 AC0 可启动性硬性验收（禁止无声退出）；③交付物清单补诊断版与 README 故障排查章节；AC1–AC7 沿用。
>
> **v2 → v3（HYPE-46，2026-11-08）**：①新增 **F7 安装后开机自启**（用户明确需求）；②新增 **F8 启动后右下角弹窗**展示本次开机用时；③新增 **F9 时钟数据源兼容层**——现场反馈 `QueryInterruptTime` 在部分 Windows 11 版本上已不从 `kernel32.dll` 导出，v0.2.0 因此无法启动，本版把"取不到就失败"改为"分层降级"，并把实际生效的数据源写入启动日志；④安装包产物更名 `boot-tool-setup.exe`（Inno Setup 7 警告 `setup.exe` 会被 Windows 应用兼容层 shim 加载，存在 DLL 劫持面）；⑤AC8 相应更名，新增 AC9–AC11。发布 tag **v0.3.1**（同内容，仅修一处非 Windows 构建可移植性问题）。


### 1. 背景与目标

**背景**：用户需要知道电脑"什么时候开的机、开了多久"，系统自带信息分散在任务管理器、`systeminfo`、事件查看器里，且口径不统一（含不含睡眠时间经常对不上）。上一轮交付用户反馈"安装包打不开"，暴露两个问题：交付形态预期错位（只给了单文件 exe）、启动失败无可见报错——本轮已在需求层修复（见 §3、AC0）。

**目标用户**：普通 Windows 用户 + 需要关注机器运行状态的运维/开发人员。

**业务目标与成功指标**：
- 开机时刻与系统权威来源（任务管理器"启动时间"）误差 ≤ 1 秒
- 时长显示在任意时刻误差 ≤ 1 秒，连续运行 7 天不漂移
- 双击后 ≤ 3 秒出现主窗口，任何失败可见可查（AC0）
- 启动后 3 秒内出数，常驻资源占用可忽略（见 §6）

### 2. 数据采集口径（关键，技术方案必须遵守）

| 概念 | 定义 | 采集方式 |
|---|---|---|
| 开机时刻 | 本次内核启动的绝对时刻 | 运行时由单调时钟 **`QueryInterruptTime`（含睡眠）** 实时推导；WMI `LastBootUpTime` / `systeminfo` 仅作人工对账基准，**不作运行时依赖**【修订：沿用上轮复核结论，WMI 实时查询有数百 ms～秒级延迟，威胁 3 秒出数】 |
| 本次开机时长 | `当前时刻 − 开机时刻` | 由开机时刻实时计算；**含睡眠/休眠时间**（与任务管理器"正常运行时间"一致） |
| 纯运行时长（P1） | 剔除睡眠/休眠后的实际运行时间 | `QueryUnbiasedInterruptTime` 或累加电源事件 |
| 累计开机时长（P1） | 跨会话累加的历史总时长 | 本地持久化：关机/退出前写入，启动时读取合并；断电场景下次启动自愈 |

**口径硬性要求**（技术方案需逐条说明实现方式）：
1. "本次开机时长"与任务管理器"正常运行时间"同口径（含睡眠），否则视为缺陷。
2. 睡眠/唤醒、休眠/恢复后数值连续，不重置、不跳变。
3. 意外断电/强杀进程不损坏已持久化数据；写入需原子（临时文件+替换或 WAL 类做法）。【P1 生效，本期标注 N/A】
4. 时区变化、夏令时切换不引起开机时刻跳变（单调时钟为主、墙钟仅用于展示）。
5. 【v3 新增】**口径数据源必须可降级**：同一口径（含睡眠的单调计时）允许按 `kernelbase!QueryInterruptTime → kernel32!QueryInterruptTime → kernel32!GetTickCount64` 逐级回退，**任何一个入口缺失都不得导致程序不可用**；实际生效的数据源必须写入启动日志与诊断输出，便于现场定位（见 AC11）。


### 3. 功能范围

**P0（MVP，本期必须）**
- F1 开机时刻展示：本次开机的日期时间
- F2 本次开机时长展示：实时刷新（天→秒，秒级常显，尾零省略；英文 `3d 4h 5m 6s`）
- F3 口径对齐：与任务管理器启动时间/正常运行时间一致
- F4 睡眠/休眠恢复后正确续算
- **F5【新增】双交付形态**：绿色单文件 `boot-tool.exe`（双击即用）+ **安装包 `boot-tool-setup.exe`**（安装向导、开始菜单快捷方式、卸载项）。依据：用户明确称"安装包"，上一轮仅单文件 exe 造成预期错位
- **F6【新增】启动失败可见性**：任何启动失败/内部错误必须弹出可见错误对话框并写入日志（`%TEMP%\boot-tool.log`），**禁止无声退出**——上一轮"打不开"暴露的正是此缺口
- **F7【v3 新增】安装后开机自启**：安装包默认勾选"开机时自动启动"（用户可在安装向导取消），写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（**免管理员**，属于 Windows 标准"启动应用"位置，任务管理器可见可关）；卸载时自动移除。绿色版可手动执行 `boot-tool.exe --install-startup` / `--uninstall-startup` 达到同样效果
- **F8【v3 新增】启动后右下角弹窗**：以自启方式启动时，等待桌面就绪约 3 秒后在**主屏工作区右下角**弹出卡片，展示"本次开机用时"（大号数字）+ 开机时刻 + "点击查看详情"；约 10 秒后自动消失，弹出期间不抢焦点、不占任务栏/Alt-Tab；点击卡片打开主窗口。手动双击启动仍直接打开主窗口（不弹卡片）
- **F9【v3 新增】数据源兼容层**：`QueryInterruptTime` 不再硬依赖单一 DLL 导出，按 `kernelbase → kernel32 → GetTickCount64` 降级；实际数据源写日志。依据：HYPE-46 现场报错 `stage: clock FAILED: QueryInterruptTime: Failed to find QueryInterruptTime procedure in kernel32.dll`（Windows 11 10.0.26300 实测 `kernel32.dll` 已无该导出、仅 `kernelbase.dll` 有）

### 4. 使用场景

1. **查看本次开了多久**：用户早上开机，晚上确认机器连续跑了多久 → 打开工具一眼看到开机时刻和时长。
2. **核对是否该重启**：机器连续运行多天 → 看本次/累计时长决定是否重启。
3. **对账**：用户怀疑任务管理器数据不准 → 本工具与其口径一致，可交叉验证。
4. **【新增】首次安装**：用户下载 `boot-tool-setup.exe` 安装 → 开始菜单启动 → 若双击打不开，按 README 排障或运行诊断版定位。
5. **【v3 新增】日常开机（主场景）**：装好之后不用管——每次登录 Windows，右下角自动弹出"本次开机用时"，看一眼即可收掉；想知道更多细节就点一下卡片打开主窗口。

### 5. 验收标准

- **AC0【新增，硬性】可启动性**：双击 `boot-tool.exe` 与 `boot-tool-setup.exe` 安装后的快捷方式，均 ≤ 3 秒出现主窗口、无黑窗；任何启动失败必须弹出可见错误对话框并写日志，**禁止无声退出**。AC0 不通过，其余验收不开始
- AC1：开机时刻与任务管理器"启动时间"相差 ≤ 1 秒（冷启动、重启、睡眠恢复各验一次）
- AC2：时长显示误差 ≤ 1 秒；连续运行 7 天无累积漂移
- AC3：睡眠 4 小时后唤醒，"本次开机时长"正确包含这 4 小时且无跳变
- AC4：强制断电后重启，累计数据不损坏、不重复累加（**随 P1 实现时验收，本期 N/A**）
- AC5：系统时区切换后，开机时刻展示仍正确
- AC6：启动后 3 秒内显示首屏；空闲 CPU < 0.1%、内存 < 50MB（参考目标，不阻塞验收，真机实测后回填基线）
- AC7：Windows 10/11 中英文系统下展示与功能正常
- **AC8【新增】安装包验收**：`boot-tool-setup.exe` 在 Win10/11 完整走完安装向导，开始菜单出现快捷方式、控制面板可卸载，安装后启动通过 AC0
- **AC9【v3 新增】开机自启**：安装包默认勾选"开机时自动启动"时，`HKCU\...\Run` 出现 `"<安装目录>\boot-tool.exe" --autostart`；卸载后该值消失；安装向导取消勾选则不写入；`--install-startup` / `--uninstall-startup` 可独立完成注册/注销并弹出可见结果提示
- **AC10【v3 新增】右下角弹窗**：以 `--autostart` 启动后 ≤ 5 秒出现右下角卡片（主屏工作区内、距右侧/底部各 16px、不遮挡任务栏），内容为本次开机用时（秒级）+ 开机时刻 + "点击查看详情"；约 10 秒自动消失且进程退出；点击卡片打开主窗口；弹窗不抢焦点、不在任务栏出现按钮。重复双击程序不会出现第二个窗口（激活已有实例）
- **AC11【v3 新增】数据源兼容**：在 `kernel32.dll` 无 `QueryInterruptTime` 导出的 Windows 版本（现场为 10.0.26300）上程序可正常启动，日志出现 `stage: clock ok (source=kernelbase.dll!QueryInterruptTime)`；三个数据源全部缺失时才允许报错退出，且必须弹出可见错误框并写明每个尝试过的数据源

### 6. 非功能需求

- 资源占用：常驻内存 < 50MB，空闲 CPU < 0.1%（**假设，待实测校准**）
- 兼容：Windows 10 1809+ 与 Windows 11 x64
- 无网络依赖、无管理员权限要求（基础功能）；不上传任何数据
- 崩溃不拖垮系统；失败可见可查（对话框 + `%TEMP%\boot-tool.log`）

### 7. 开放问题与已拍板决策

**已拍板（不再讨论）**：
1. 交付形态：**双交付**（绿色单文件 + 安装包）——用户"安装包打不开"反馈的直接对策
2. 历史会话/导出：本期砍掉归 P1；AC4 随 P1 验收
3. 展示格式：`3天4小时5分6秒`（尾零省略），英文 `3d 4h 5m 6s`
4. AC6 资源指标：参考目标、不阻塞验收
5. 【v3】开机自启**默认勾选**：用户明确要求"安装后开机自动启动"；仍保留在安装向导中取消勾选的自由
6. 【v3】弹窗节奏：桌面就绪等待 **3 秒**、停留 **10 秒**（可配置常量，改值不需改结构）
7. 【v3】安装包产物更名 `boot-tool-setup.exe`：Inno Setup 7 对名为 `setup.exe` 的产物给出安全警告（Windows 应用兼容层会 shim 加载 `version.dll` 等，存在劫持面）
8. 【v3】时钟数据源降级顺序 `kernelbase → kernel32 → GetTickCount64`：前两者 100ns、第三者 1ms，同属"自启动起算、含睡眠"的计数族，秒级展示下无可见差异

**遗留开放问题**：
1. 安装包技术选型（Inno Setup / NSIS / 其它）→ **已由技术方案 v2 回答：Inno Setup 7.1.1，见 `docs/design.md` §4 与决策 ADR-1**
2. 上一轮"打不开"的确切根因仍未定位（SmartScreen / 下载损坏 / 静默失败三选一）→ **v3 部分定位：`QueryInterruptTime` 取不到导致的 clock 阶段失败已在现场日志复现（HYPE-46），本版修复；其余路径仍由 F6 兜底**
3. 【v3，P1】弹窗是否要附带"比上次开机快/慢"的历史对比（依赖 P1 累计数据）

---

**事实与假设说明**：§2 的 `QueryInterruptTime` 口径方案已通过 Linux 冒烟对账（与 `uptime -s` 秒级一致）与 Windows 双源交叉校验（`v0.3.0` 单测比对 `GetTickCount64`，误差 < 2 秒）；AC6 资源指标为**待实测项**；AC9–AC11 已在本机（Windows 11 10.0.26300 x64）实机验证，记录见 `docs/test-plan.md` §C。其余为需求定义。
